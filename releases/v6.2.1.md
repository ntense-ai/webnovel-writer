# v6.2.1 - Fix intermittent Windows access denial during chapter commits

## Release Scope

This release covers `v6.2.0..v6.2.1`, primarily fixing issue #125.

## Changes for Authors

- Fix intermittent `WinError 5 (Access is denied)` during chapter commits on Windows. When VSCode, antivirus software, or a sync client briefly locks story data such as `.webnovel/memory_scratchpad.json` or `state.json`, the system now waits and retries instead of failing immediately (#125).
- If the project is inside a VSCode workspace, consider adding `**/.webnovel/**` to `files.watcherExclude` to reduce lock conflicts further. Keep projects outside synchronized folders such as OneDrive where possible.

## Do Existing Projects Need Changes?

No. Existing book projects continue to work without migration.

## For Maintainers

- `security_utils.atomic_write_json`: retry `os.replace` on `PermissionError` with exponential backoff (20ms→500ms, 10 attempts, roughly a 2.6-second window), then propagate the error when exhausted. Other exceptions are not swallowed. All JSON projections, including state.json, memory_scratchpad.json, and summaries, share this writer and benefit from the fix.
- Add four cases in `scripts/tests/test_security_utils_atomic.py`: recovery from transient locks and verification of the backoff sequence; persistent locks exhausting retries with `AtomicWriteError` while preserving the original content; unchanged test-sandbox fallback behavior; and reproduction with a real Windows locked handle (win32 only).
- Synchronize version metadata to `6.2.1`.
