# v6.2.0 - Clearer chapter results and better recovery after failures

## Release Scope

This release covers all changes from `v6.1.0` to the release commit, not just the final version-bump commit.

## Changes for Authors

- Easier-to-read command results. Initialization, planning, writing, and review use a consistent final report to distinguish completed, partially completed, action required, and not completed.
- Better recovery after writing failures. Rerunning `/webnovel-write <chapter-number>` first checks which steps completed reliably and resumes from the failure where possible.
- Less intrusive progress reporting. The system continues by default and asks only when creative direction, factual choices, overwrite risks, or blocking review issues need your decision.
- More reliable intermediate writing and review results. The system checks chapter text, review results, fact extraction, chapter commits, and story-data synchronization more strictly.
- Safer minimal writing mode. Skipping full review produces an explicit skip record instead of pretending a full review passed.
- More selective context reading. Lighter Skill and Agent prompts reduce unrelated reference material and help long workflows stay focused.
- Clearer troubleshooting. Unrecoverable failures point to redacted logs; documentation now explains final reports, checkpoint recovery, and operations.

## Do Existing Projects Need Changes?

No. Existing book projects remain usable without migrating `.story-system/`, `.webnovel/`, chapter text, outlines, or setting bibles.

## Who Should Upgrade?

- Authors who often write several chapters in sequence and want a clear answer to “Is this chapter actually finished?”
- Users unsure how to recover after interrupted writing, blocked reviews, or failed story-data synchronization.
- Authors of long-form projects that rely on Story System to track facts and foreshadowing.

## Known Impact

- Existing `/webnovel-*` primary commands are not renamed.
- Blocking review, chapter commit, and story-data synchronization checks are not relaxed.
- Final reports hide internal JSON and long logs. Consult `.webnovel/logs/run_last.log` when troubleshooting is necessary.

## For Maintainers

- Add an author-friendly reporting pipeline: `author_glossary.py`, `error_catalog.py`, `review_author_view.py`, and `user_report.py`.
- Add chapter recovery and logging: `run_ledger.py` and `run_logger.py`.
- Add unified CLI subcommands: `user-report`, `run-ledger`, and `run-log`.
- Tighten structured boundaries for commit artifacts, projection writers, write-gate, postcommit, and the review pipeline.
- Streamline init, plan, write, review, query, learn, dashboard, and doctor Skills, plus context/data/reviewer/deconstruction Agents.
- Add reference-loading maps, region-read rules, context-reduction audits, and Claude Code tool-baseline documentation.
- Add prompt-integrity tests, unit tests, and behavioral evals covering artifact ownership, minimal writing, projection retries, blocking reviews, checkpoint recovery, and log redaction.
- Synchronize version metadata to `6.2.0`.
- Change the `Plugin Release` workflow to release automatically after pushes to `master`, retaining a manual fallback.
