## I. Common Tropes to Avoid or Reverse

| Trope | Problem | Frequency |
|------|------|---------|
| Protagonist has a power that sees through rules | Makes deduction too easy | Very high |
| Rules can always be defeated | No genuine threat | High |
| Teammates die one by one | Formulaic deaths | High |
| Escape at the end | Predictable ending | High |
| Rules originate from an evil god/curse | Repetitive explanation | Medium |
| Protagonist is the sole survivor | Little variety | Medium |

## II. Unconventional Constraints (Choose at Least One per Project)

### 2.1 Protagonist Ability Limits

| ID | Anti-trope rule | Creative driver | Example |
|----|-----------|---------|------|
| RM-001 | Cannot see complete rules | Trial, error, and deduction | Missing manual pages |
| RM-002 | Special ability has severe side effects | Every use requires a trade-off | Seeing through a rule erases a memory |
| RM-003 | Rules learn the protagonist's ability | A tactic works only once | Rules adapt to each solution |
| RM-004 | The protagonist is part of the rules | Their behavior changes the rules | Their death triggers a new rule |
| RM-005 | No special ability | Intelligence and observation alone | An ordinary person's viewpoint |

### 2.2 Rule Limits

| ID | Anti-trope rule | Creative driver | Example |
|----|-----------|---------|------|
| RM-006 | Rules cannot be defeated, only adapted to | Survival rather than victory | Rules are immutable world laws |
| RM-007 | Rules evolve or mutate | Dynamic threats | Every death updates the rules |
| RM-008 | Rules conflict | Counter one rule with another | Obeying A inevitably violates B |
| RM-009 | Punishment is delayed | Uncertain timing | A violation triggers punishment at a random later time |
| RM-010 | True meaning differs from literal wording | Wordplay | “Do not speak” actually means “Do not lie” |

### 2.3 Environment/Team Limits

| ID | Anti-trope rule | Creative driver | Example |
|----|-----------|---------|------|
| RM-011 | A traitor is among the group | Crisis of trust | Someone deliberately triggers rules |
| RM-012 | Escape is not the end | Rules follow survivors | Rules take effect in reality after escape |
| RM-013 | Time loop | Repeated attempts with costs | Death resets events but memories are incomplete |
| RM-014 | The rule-governed space expands | Urgency | Its area doubles every hour |
| RM-015 | Compliance has a cost too | No safe choice | Following rules slowly erodes humanity |

### 2.4 Information Limits

| ID | Anti-trope rule | Creative driver | Example |
|----|-----------|---------|------|
| RM-016 | The protagonist does not know they are inside | Discovering the truth comes first | They think the world is normal |
| RM-017 | The manual is false or incomplete | Information cannot be fully trusted | The manual itself is a trap |
| RM-018 | Different people see different rules | Information asymmetry | Everyone sees only a subset |
| RM-019 | Rules are forgotten | Memory management | Knowledge of a rule gradually fades |
| RM-020 | Speaking a rule invalidates it | Silent strategic contest | Telling others changes the rule |

## III. Unconventional Payoffs (Alternatives to Escaping)

### 3.1 Deductive Payoffs

| ID | Pattern | Description | Example |
|----|---------|------|------|
| RM-S01 | Reverse inference | Infer rules from outcomes | Death patterns reveal a rule |
| RM-S02 | Rule combination | Use interacting effects | Rule A + rule B = safe zone |
| RM-S03 | Boundary testing | Find exact limits | What precisely counts as “speaking”? |
| RM-S04 | Origin deduction | Infer why rules exist | Rules embody someone's obsession |
| RM-S05 | False-rule detection | Separate genuine rules from fakes | False instructions are mixed into the manual |

### 3.2 Strategic Payoffs

| ID | Pattern | Description | Example |
|----|---------|------|------|
| RM-S06 | Rules against rules | Exploit conflicts | Rule A's punishment cancels rule B |
| RM-S07 | Human contest | Strategy between survivors | The first violator dies first |
| RM-S08 | Contest with the rule-maker | Discover the will behind the rules | An entity is playing a game |
| RM-S09 | Information contest | Exploit asymmetry | Pretend not to know a rule |
| RM-S10 | Timing contest | Exploit temporal properties | Complete the objective before punishment arrives |

### 3.3 Reversal Payoffs

| ID | Pattern | Description | Example |
|----|---------|------|------|
| RM-S11 | Rule reversal | Reveal a rule's true meaning | “Do not open the door” protects those outside |
| RM-S12 | Identity reversal | Reveal protagonist/NPC identity | The protagonist created the rules |
| RM-S13 | Objective reversal | Escape is not the real goal | Escaping causes a greater catastrophe |
| RM-S14 | Timeline reversal | Reveal the order of events | This is the Nth loop |
| RM-S15 | Reality reversal | Reveal the space's relationship to reality | The rule-governed space is the real world |

### 3.4 Cost-Based Payoffs

| ID | Pattern | Description | Example |
|----|---------|------|------|
| RM-S16 | Sacrifice for information | Trade life for crucial knowledge | A teammate conveys a rule before dying |
| RM-S17 | Partial compliance | Accept some punishment for freedom | Deliberately trigger a minor penalty |
| RM-S18 | Transfer the cost | Move punishment to someone/something else | A substitute bears the penalty |
| RM-S19 | Delayed cost | Act now, pay later | Borrow future lifespan |
| RM-S20 | Shared burden | Divide punishment | Several people share one penalty |

## IV. Combination Examples

### Example 1: Information-Asymmetry Horror

```
Anti-trope rules: RM-018 (different people see different rules) + RM-020 (speaking invalidates rules)
Payoffs: RM-S09 (information contest) + RM-S07 (human contest)

Core conflict: Everyone knows only some rules but cannot share them
Creative driver: How can people cooperate without direct communication?
Differentiation: Social-deduction horror focused on interpersonal strategy
```

### Example 2: Evolving-Rule Horror

```
Anti-trope rules: RM-007 (evolving rules) + RM-003 (rules learn the protagonist)
Payoffs: RM-S03 (boundary testing) + RM-S06 (rules against rules)

Core conflict: Every solution makes the rules harder
Creative driver: How can one survive continuously evolving rules?
Differentiation: Dynamic threats make every loop different
```

### Example 3: Cost-Based Horror

```
Anti-trope rules: RM-015 (compliance costs too) + RM-006 (rules cannot be defeated)
Payoffs: RM-S17 (partial compliance) + RM-S20 (shared burden)

Core conflict: Compliance and violation both cost something; only the kind of cost can be chosen
Creative driver: How can costs be minimized?
Differentiation: No safe options; every decision has weight
```

### Example 4: Identity Horror

```
Anti-trope rules: RM-004 (protagonist is part of the rules) + RM-016 (unaware of the rule-governed space)
Payoffs: RM-S12 (identity reversal) + RM-S15 (reality reversal)

Core conflict: The protagonist discovers they are the rules' core
Creative driver: How do they confront the truth that they are the monster?
Differentiation: A viewpoint reversal from victim to perpetrator
```

## V. Rule Design Templates

### 5.1 Basic Template

Original placeholder tokens are preserved; the English labels explain their roles.

```markdown
[Rule Name]
Trigger: {什么情况下规则生效}
Requirement: {规则的具体要求}
Penalty: {违反规则的后果}
Hidden meaning: {规则的真正目的/深层含义}
Exploitable opening: {主角可以利用的漏洞/边界}
```

### 5.2 Design Principles

1. **Internal logic**: Every rule needs a reason to exist.
2. **Deducibility**: Readers should be able to infer it.
3. **Clear boundaries**: Limits should be testable.
4. **Explicit costs**: Punishments should be concrete.
5. **Exploitability**: Leave room for creative use.

### 5.3 Complexity Control

| Length (Chinese characters) | Core rules | Hidden rules | False rules |
|------|-----------|-----------|---------|
| Short: under 50,000 | 3–5 | 1–2 | 0–1 |
| Medium: 50,000–200,000 | 5–8 | 2–3 | 1–2 |
| Long: over 200,000 | 8–12 | 3–5 | 2–3 |

## VI. Usage Guide

### 6.1 Selection Process

1. Choose 1–2 unconventional constraints.
2. Choose 2–3 unconventional payoff patterns as the main modes.
3. Design 3–5 core rules.
4. Give each rule an exploitable opening.
5. Check for interesting interactions between rules.

### 6.2 Pitfalls

- ❌ Rules that are too easy to defeat.
- ❌ Punishments that are not frightening enough.
- ❌ A protagonist so powerful that rules are meaningless.
- ❌ Unconnected rules.
- ✅ Genuine threats.
- ✅ Solutions that demand a cost.
- ✅ Interesting rule interactions.
- ✅ Victory through intelligence rather than special power.
